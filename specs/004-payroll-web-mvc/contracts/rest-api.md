# Контракт HTTP API: `/api/Payroll`

База: `http://localhost:8080`. Формат: `application/json`; `{id}` — `employeeId`. Повідомлення — українською.

| Метод | Шлях | Тіло запиту | Успіх |
|-------|------|-------------|-------|
| GET | `/api/Payroll` | — | 200 `{"employees":[{"employeeId":"E1","fullName":"Іван Петренко"}]}` (порожній список — `[]`) |
| POST | `/api/Payroll` | `{"employeeId":"E1","fullName":"Іван Петренко"}` | 201 `{"message":"…"}` |
| PUT | `/api/Payroll/{id}` | `{"employeeId":"E1","fullName":"Новий ПІБ"}` (`employeeId` необов'язковий, але якщо є — має дорівнювати `{id}`) | 200 `{"message":"…"}` |
| DELETE | `/api/Payroll/{id}` | — | 200 `{"message":"…"}` |
| GET | `/` | — | 200 `index.html` (статика з `public`) |

## Відмови

| Код | Причина | Умови |
|-----|---------|-------|
| 400 | дані не пройшли перевірку | R1 (порожнє/пробіли/`null`/нечитабельне тіло), R2 (дублікат), R3 (id у тілі ≠ id у шляху) |
| 404 | об'єкт не знайдено | R5: PUT/DELETE неіснуючого `{id}` |
| 409 | зміна заборонена | R4: наказ нечинний |
| 500 | помилка сховища | збій SQLite |

Тіло відмови: `{"message":"<пояснення українською>"}`.

## Порядок перевірки
R4 → R5 (PUT/DELETE) → R1, R3, R2. За відмови дані не змінюються.

## Ролі
- Javalin лише маршрутизує, серіалізує `ApiResponse.body()` і виставляє `ApiResponse.status()`.
- Нечитабельне/порожнє тіло POST/PUT → контролеру передаються `null` → 400 за R1.
