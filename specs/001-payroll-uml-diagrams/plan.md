# План реалізації: UML-діаграми нарахування заробітної плати

**Гілка**: `001-payroll-uml-diagrams` | **Дата**: 2026-09-21 | **Специфікація**: [spec.md](./spec.md)

**Вхідні дані**: Специфікація функціональності з `specs/001-payroll-uml-diagrams/spec.md`.

## Підсумок

Створити п'ять погоджених україномовних документаційних артефактів для локального навчального
прикладу нарахування зарплати: PlantUML-діаграму варіантів використання, Mermaid-діаграми класів,
послідовності та станів, а також книгу Excel із CRC-картками. Єдина канонічна модель містить
`Employee`, `DirectorOrder`, `PayrollSheet`, `PayrollCalculation`, `Receipt` і `PayrollRule`.
Пояснювальні написи залишаються українськими, а програмні ідентифікатори — англійськими.

## Технічний контекст

**Мова/версія**: Java 17+ для локальної валідації й сумісності з конституцією; самі діаграми є текстовими PlantUML і Mermaid файлами  

**Основні залежності**: PlantUML CLI для `usecase.puml`; Mermaid CLI для `.mmd`; Apache POI або сумісний локальний засіб читання XLSX лише для перевірки `crc.xlsx`  

**Зберігання**: Файли документації в каталозі `docs/`; бази даних і зовнішні сервіси відсутні  

**Тестування**: Локальна CLI-перевірка синтаксису PlantUML і Mermaid, цілісності XLSX та трасованості вимог між артефактами  

**Цільова платформа**: Локальне середовище розробки з JDK та командним рядком  

**Тип проєкту**: Навчальний Java-проєкт із текстовою UML-документацією  

**Цілі продуктивності**: Усі п'ять артефактів доступні для перевірки менш ніж за 1 хвилину після відкриття `docs/`  

**Обмеження**: Без реальних виплат, мережі, БД або зовнішніх інтеграцій; залежності моделей явно відображаються конструкторами або параметрами операцій; текст і пояснення українською  

**Масштаб/обсяг**: Один розрахунковий цикл, одна `PayrollSheet`, три ролі й шість ключових предметних сутностей  

## Перевірка конституції

*Шлюз: пройдено до дослідження; повторно перевірено після проєктування.*

| Принцип | Рішення | Стан |
|---|---|---|
| Мінімальна складність | Лише необхідні діаграми, одна модель предметної області й один аркуш CRC. | Пройдено |
| Єдина відповідальність | `PayrollSheet` керує складом і циклом, `PayrollRule` обчислює, `Receipt` представляє результат; відповідальності зафіксовані в CRC. | Пройдено |
| Імітація зовнішніх операцій | Функціональність не виконує зовнішніх операцій; результатом є локальні документи. | Пройдено |
| Локальний CLI | Генерування й перевірка виконуються локальними CLI-інструментами без БД чи сервісів. | Пройдено |
| Явне впровадження залежностей | `DirectorOrder` передається в `PayrollSheet`, а `PayrollRule` — в операцію розрахунку; це показано на class/sequence діаграмах. | Пройдено |
| Мова та іменування | Програмні елементи англійською, пояснення та підписи українською. | Пройдено |
| Текстова UML-документація | Чотири діаграми зберігаються у визначених текстових форматах у `docs/`. | Пройдено |
| Українська специфікація | Усі нові планові артефакти написано українською. | Пройдено |
