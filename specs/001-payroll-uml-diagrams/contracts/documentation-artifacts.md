# Контракт документаційних артефактів

## Обов'язкові файли

| Файл | Формат | Контракт |
|---|---|---|
| `docs/usecase.puml` | PlantUML | Містить акторів «Директор», «Бухгалтер», «Працівник», чотири операції та передумову чинного наказу для дій бухгалтера. |
| `docs/class.mmd` | Mermaid `classDiagram` | Містить модель із [data-model.md](../data-model.md), конструктори, атрибути/операції, остаточну операцію, усі потрібні типи зв'язків. |
| `docs/sequence.mmd` | Mermaid `sequenceDiagram` | Містить об'єкти класової діаграми та повідомлення для чотирьох операцій, включно з альтернативами помилкових сценаріїв. |
| `docs/state.mmd` | Mermaid `stateDiagram-v2` | Містить стани очікування наказу, формування відомості, готовності, нарахування, завершення та видачі квитанції. |
| `docs/crc.xlsx` | XLSX, аркуш `CRC` | Містить колонки `Class`, `Відповідальності`, `Співпрацівники` й одну картку для кожного класу. |

## Спільний словник

Структурні назви: `Employee`, `DirectorOrder`, `PayrollSheet`, `PayrollCalculation`, `Receipt`,
`PayrollRule`, `BasePayrollRule`, `StandardPayrollRule`. Пояснювальні написи українські. Заміна,
скорочення або інша транслітерація цих ідентифікаторів у будь-якому з п'яти артефактів
заборонена.

## Перевірні умови

1. Операції бухгалтера не виконуються без чинного `DirectorOrder`.
2. Повторне додавання `Employee` не змінює склад `PayrollSheet`.
3. Розрахунок неможливий для порожньої відомості.
4. `Receipt` доступний лише працівникові з завершеним `PayrollCalculation`.
5. Кожна з умов простежується щонайменше в use-case, sequence/state (за змістом) і CRC/class
   артефактах.
