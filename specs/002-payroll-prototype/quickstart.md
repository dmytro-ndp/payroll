# Швидкий старт: перевірка імітаційного прототипу

**Функціональність**: `specs/002-payroll-prototype/spec.md` | **План**: `plan.md`

## Передумови

- Встановлений JDK 17+ (команди `javac`, `java` доступні в `PATH`).
- Відкритий термінал у корені репозиторію.

## Компіляція

```sh
javac -d bin $(find src -name "*.java")
```

На Windows PowerShell:

```powershell
javac -d bin (Get-ChildItem -Recurse -Filter *.java src).FullName
```

## Запуск

```sh
java -cp bin ua.payroll.Main
```

## Сценарій ручної перевірки (щасливий шлях + відмови)

Відповідає user stories й `contracts/console-cli.md`. Вводьте рядки, коли програма запитує:

1. Ідентифікатор наказу, напр. `ORD-1` → очікується повідомлення про видання чинного наказу
   (FR-001).
2. Кількість працівників для спроби додавання: `3`.
3. Перший працівник: `EMP-1`, `Іваненко Іван` → повідомлення про успішне додавання.
4. Другий працівник: `EMP-2`, `Петренко Петро` → повідомлення про успішне додавання.
5. Третій працівник: **повторіть** `EMP-1`, `Іваненко Іван` → очікується повідомлення про
   **відмову через дублікат** (FR-003, SC-004), склад відомості лишається з 2 працівниками.
6. Підтвердіть нарахування (Enter/команда) → очікуються повідомлення про завершене нарахування
   для `EMP-1` і `EMP-2` із сумою (FR-005, FR-006).
7. Запит квитанції для `EMP-1` → очікується повідомлення про видачу квитанції з іменем і сумою
   (FR-007, FR-008).
8. Запит квитанції для працівника без нарахування, напр. невідомий `EMP-9` → очікується
   повідомлення про **відмову** без створення квитанції (FR-007, SC-005).

### Перевірка відмови через нечинний наказ (SC-003)

Запустіть програму повторно й на кроці 2 спробуйте додати працівника або розпочати нарахування
**до** введення ідентифікатора наказу (або після сценарію, що включає відкликання наказу, якщо
реалізовано) — очікується повідомлення про відмову без зміни складу відомості чи появи
нарахувань.

## Очікувані результати (критерії прийняття)

- Усі повідомлення — українською мовою, без технічних стек-трейсів (SC-006).
- Дублікат працівника ніколи не додається повторно (SC-004).
- Нарахування неможливе без чинного наказу або на порожній відомості (SC-003).
- Квитанція недоступна до завершення нарахування для конкретного працівника (SC-005).

## Автоматизована самоперевірка (без зовнішніх залежностей)

```sh
javac -d bin $(find src -name "*.java")
java -cp bin ua.payroll.SelfCheck
```

Клас `SelfCheck` (без JUnit чи інших бібліотек) викликає публічний API доменних класів напряму
й виводить підсумок перевірок українською, звіряючи сценарії успіху та відмови з
`data-model.md` і `docs/sequence.mmd`.
