# UML-діаграми нарахування заробітної плати

Цей каталог містить узгоджений набір артефактів для одного локального розрахункового циклу.
Пояснювальний текст подано українською, а програмні ідентифікатори — англійською.

## Спільний словник

| Ідентифікатор | Призначення |
|---|---|
| `Employee` | Працівник, якого включають до відомості. |
| `DirectorOrder` | Чинний наказ директора — передумова додавання та нарахування. |
| `PayrollSheet` | Відомість, що керує складом працівників і циклом нарахування. |
| `PayrollCalculation` | Результат нарахування для одного працівника. |
| `Receipt` | Квитанція, що подає завершене нарахування адресатові. |
| `PayrollRule` | Контракт обчислення нарахування. |
| `BasePayrollRule` | Абстрактна спільна основа правила нарахування. |
| `StandardPayrollRule` | Конкретне стандартне правило нарахування. |

## Локальна перевірка

```sh
java -jar plantuml.jar --check-syntax docs/usecase.puml
npx --yes @mermaid-js/mermaid-cli -i docs/class.mmd -o /tmp/class.svg
npx --yes @mermaid-js/mermaid-cli -i docs/sequence.mmd -o /tmp/sequence.svg
npx --yes @mermaid-js/mermaid-cli -i docs/state.mmd -o /tmp/state.svg
```

Книгу `crc.xlsx` слід відкрити локальним сумісним засобом читання XLSX і перевірити аркуш
`CRC` та колонки `Class`, `Відповідальності`, `Співпрацівники`.

## Підтвердження трасованості

Видача наказу, додавання працівника, нарахування та видача квитанції відображені в
`usecase.puml`, `sequence.mmd` і `state.mmd`. Учасники взаємодій мають відповідні класи в
`class.mmd`; CRC-картки фіксують відповідальність і співпрацівників кожного класу.
Відмова для нечинного наказу, дубліката, порожньої відомості та передчасної квитанції не
створює результату й не змінює стан.
