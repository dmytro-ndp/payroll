# UML-діаграми нарахування заробітної плати

Цей каталог містить узгоджений набір артефактів для одного локального розрахункового циклу.
Пояснювальний текст подано українською, а програмні ідентифікатори — англійською.

## Спільний словник

| Ідентифікатор | Призначення |
|---|---|
| `Employee` | Працівник, якого включають до відомості. |
| `DirectorOrder` | Чинний наказ директора — передумова додавання та нарахування. |
| `PayrollSheet` | Відомість, що керує складом працівників і циклом нарахування. |
| `PayrollCalculation` | Результат нарахування для одного працівника. |
| `Receipt` | Квитанція, що подає завершене нарахування адресатові. |
| `PayrollRule` | Контракт обчислення нарахування. |
| `BasePayrollRule` | Абстрактна спільна основа правила нарахування. |
| `StandardPayrollRule` | Конкретне стандартне правило нарахування. |

## Локальна перевірка

```sh
java -jar plantuml.jar --check-syntax docs/usecase.puml
npx --yes @mermaid-js/mermaid-cli -i docs/class.mmd -o /tmp/class.svg
npx --yes @mermaid-js/mermaid-cli -i docs/sequence.mmd -o /tmp/sequence.svg
npx --yes @mermaid-js/mermaid-cli -i docs/state.mmd -o /tmp/state.svg
```

Книгу `crc.xlsx` слід відкрити локальним сумісним засобом читання XLSX і перевірити аркуш
`CRC` та колонки `Class`, `Відповідальності`, `Співпрацівники`.

## Підтвердження трасованості

Видача наказу, додавання працівника, нарахування та видача квитанції відображені в
`usecase.puml`, `sequence.mmd` і `state.mmd`. Учасники взаємодій мають відповідні класи в
`class.mmd`; CRC-картки фіксують відповідальність і співпрацівників кожного класу.
Відмова для нечинного наказу, дубліката, порожньої відомості та передчасної квитанції не
створює результату й не змінює стан.

### Матриця вимог

| Вимога | Однозначне підтвердження |
|---|---|
| FR-001 | `usecase.puml`, `class.mmd`, `sequence.mmd` і `state.mmd` є чотирма заданими діаграмами в `docs/`. |
| FR-002 | `usecase.puml` містить акторів «Директор», «Бухгалтер», «Працівник» і сценарії для кожного. |
| FR-003 | `usecase.puml` містить сценарії додавання працівника, нарахування й отримання квитанції. |
| FR-004 | `usecase.puml` пов'язує `IssueOrder` із `CheckOrder`, який включено до обох операцій бухгалтера. |
| FR-005 | `class.mmd` містить класи `Employee`, `DirectorOrder`, `PayrollSheet`, `PayrollCalculation`, `Receipt`, інтерфейс `PayrollRule`, абстрактний `BasePayrollRule`, конструктори та члени. |
| FR-006 | `class.mmd` позначає `DirectorOrder.isActive()` як `final` і містить наслідування, реалізацію, залежність, агрегацію та композицію. |
| FR-007 | `class.mmd` розподіляє доменні відповідальності між класами, а `crc.xlsx` документує відповідальності й співпрацівників. |
| FR-008 | `sequence.mmd` показує повідомлення для видання наказу, додавання працівника, нарахування й видачі квитанції між об'єктами класової моделі. |
| FR-009 | `state.mmd` містить усі шість заданих станів, переходи для чотирьох операцій і відмови без зміни стану. |
| FR-010 | Спільний словник цього файла збігається з ідентифікаторами в усіх чотирьох діаграмах. |
| FR-011 | `crc.xlsx`, аркуш `CRC`, містить картки для всіх класів і колонки `Class`, `Відповідальності`, `Співпрацівники`. |
| FR-012 | Пояснення в діаграмах і CRC українською, а ідентифікатори моделі — англійською. |
| FR-013 | `state.mmd` починається переходом `[*] --> WaitingForOrder` і завершується переходом `CalculationCompleted --> [*]`. |
| SC-001 | П'ять артефактів доступні безпосередньо в `docs/`: чотири діаграми та `crc.xlsx`. |
| SC-002 | Видача наказу, додавання працівника, нарахування й квитанція узгоджено відображені в `usecase.puml`, `sequence.mmd` і `state.mmd`. |
| SC-003 | Учасники `sequence.mmd` (`DirectorOrder`, `PayrollSheet`, `StandardPayrollRule`, `PayrollCalculation`, `Receipt`) визначені в `class.mmd`. |
| SC-004 | Аркуш `CRC` у `crc.xlsx` містить назву, відповідальності та співпрацівників для кожного класу. |
| SC-005 | Рядки FR-001—FR-013 і SC-001—SC-004 цієї таблиці надають однозначні підтвердження для всіх функціональних вимог і критеріїв успіху. |
